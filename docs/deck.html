The Problem

Why Public Blockchains & Legacy Portals Fail Procurement

Public Chains (Ethereum / Solana)

  • Bids sit in plaintext in mempools and state.
  • Competitors snipe & undercut by $1 in the final block.
  • Suppliers expose proprietary pricing structures forever.

Centralized RFQ Portals

  • Vendors must blindly trust portal operators not to leak bids.
  • No cryptographic proof that the lowest valid bid won.
  • Auditing compliance forces leaking confidential internal thresholds.

The Midnight Solution

Dual-Ledger Privacy + Selective Disclosure by Construction

  • Zero-Knowledge Range-Proved Sealed Bids: Bidders prove 0 < amount <= reserve_cap locally via private witness; only the salted persistentHash commitment enters the public ledger.
  • Anti-Sniping & Anti-Self-Bidding: Compact circuits enforce pk != issuer_pk, reject duplicate bids per derived identity, and lock commitments before the reveal window opens.
  • Deterministic Lowest-Bid Award: During reveal, bidders open commitments; tampered amounts or salts fail cryptographic verification immediately.
  • Selective Compliance Disclosure: The winner proves winning_bid ∈ [min_band, max_band] using a private auditor policy witness — disclosing only compliance_hash and compliance_ok = true.

export circuit submit_sealed_bid(): [] { assert(phase == TenderPhase.open, "Tender is not accepting sealed bids"); const sk = local_secret_key(); // Private witness — NEVER disclosed const pk = derive_pk(sk); const amount = get_bid_amount(); // Private witness — NEVER disclosed const salt = get_bid_salt(); // Private witness — NEVER disclosed assert(amount > 0 && amount <= reserve_cap, "ZK range proof"); const commitment = make_bid_commitment(tender_id, pk, amount, salt); store_bid_receipt(amount, salt); // Persisted strictly in local state slot0_bidder = disclose(pk); // Explicit compiler-checked disclosure slot0_commit = disclose(commitment); }
