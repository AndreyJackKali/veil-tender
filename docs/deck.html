The Problem

Why Public Chains & Legacy RFQ Portals Break Procurement

Public Blockchains (EVM / Solana)

  • Bids sit in plaintext inside mempools and on-chain storage.
  • Competitors snipe & undercut by $1 in the final block.
  • Suppliers expose proprietary pricing margins permanently.
  • Publishing audit bands lets bidders game the exact ceiling.

Centralized RFQ Portals & Naive ZK

  • Vendors must blindly trust operators not to leak or rig awards.
  • No cryptographic proof that the lowest valid bid won.
  • The Self-Attestation Loophole: Without pre-locked policy commitments, a winner could prove compliance against a forged wide range [$1, $100k]!

Compiler-Enforced Information-Flow Privacy

Zero Witness Leakage by Construction (veil_tender.compact)

export circuit lock_compliance_policy(): [] { assert(phase == TenderPhase.open || phase == TenderPhase.revealing, "Policy must be locked prior to award"); assert(!policy_locked, "Compliance policy already locked"); assert(derive_pk(local_secret_key()) == issuer_pk, "Only issuer can lock compliance policy"); const band = get_audit_band(); // Private witness — NEVER disclosed const policy_salt = get_policy_salt(); // Private witness — NEVER disclosed assert(band[0] > 0 && band[0] <= band[1] && band[1] <= reserve_cap, "Valid policy corridor"); policy_commitment = disclose(make_policy_commitment(tender_id, band[0], band[1], policy_salt)); policy_locked = true; }

In prove_compliance_band(), if policy_locked is true, the winner MUST prove in ZK that their private [min_band, max_band, policy_salt] opens policy_commitment AND contains winning_bid — closing the forged self-attestation attack permanently.

Security Invariants & Adversarial Testing

9 Live Exploit Vectors Rejected Deterministically

Core 4 Tour Exploits (Proved in Browser + Vitest)

  • Double-Bid: Duplicate bidder identity across slots 0/1/2 rejected (Bidder already submitted).
  • Bid Tamper: Undercut reveal or wrong salt rejected (Commitment mismatch).
  • Premature Reveal: Calling reveal_bid() during open phase rejected.
  • Compliance Bypass: Forged wide range [$1, $100k] rejected by policy_commitment.

5 Additional Hardened Invariants

  • Exceed Reserve Cap / Zero Bid: ZK range proof rejects 0 and cap + 1.
  • Issuer Self-Bid: derive_pk(sk) != issuer_pk enforced inside circuit.
  • Settle Unattested: Escrow refuses settlement while compliance_ok == false.
  • Wrong Policy Salt / Out-of-Band: Blocked even with valid bounds or valid salt.
  • Offline Receipt Tampering: CLI & browser verifiers reject altered bids, hashes, or flags.
